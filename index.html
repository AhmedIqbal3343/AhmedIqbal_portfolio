Agent systems for web development

I develop and maintain the LLM-driven agent system DX Creativ uses to turn client briefs into working websites. Two client WordPress sites were built and deployed through it.

My role
AI Engineer: agent development and maintenance
Context
Production system used on client work
Status
In use; two delivered sites live

Problem

Small-business websites at an agency share a lot of structure: service pages, brand or location pages, FAQs, and call and WhatsApp contact paths. Building each by hand is slow. A language model can draft much of it, but a single model call gives inconsistent structure, invented details and pages that need rework.

Why it mattered

If the agent's output can't be trusted, the time saved in generation is spent again on review and fixes. Reliability is what makes the automation worth using on paid client work.

What I did

  • Iterate on prompt design, tool orchestration and output-quality evaluation to raise the share of agent tasks that complete correctly.
  • Maintain and extend the existing production AI codebase, refactoring pipeline components.
  • Diagnose and fix failure modes that surfaced during real client use.
  • Build and deploy client websites through the agent, including QuickJumpStart and GlanPawsPets.

Who did what

My work

Agent prompts, orchestration, evaluation and pipeline fixes. Building and deploying the sites through the agent.

The agent

Produced the site pages and content from the brief, under that workflow.

Client & agency

Business details such as services, prices, phone numbers and photos. Both sites carry DX Creativ's footer credit.

What the sites show

  • QuickJumpStart: WordPress with Elementor. A jump-start request form (name, phone, location, optional vehicle make), call and WhatsApp actions throughout, pages for individual car brands, Dubai coverage areas and an FAQ.
  • GlanPawsPets: WordPress with Elementor. A page per species groomed, fixed-price packages that open a pre-filled WhatsApp booking, covered areas and an FAQ.

Checked on the live sites, October 2026.

Evaluation

Output-quality evaluation is part of the loop. Failures found during real client use feed back into prompt and pipeline changes instead of being patched by hand on each site.

Outcome & limits

Both sites are live. No task-success or time-saved figures are published here.

Final-year project · BS Software EngineeringIn development

AcademicGuard

An NLP system that classifies research-paper text as AI-generated or human-written, using Transformer models I fine-tuned with Hugging Face and PyTorch, and turns the result into a per-section integrity report.

My role
Data preparation, fine-tuning, evaluation, parsing, reporting
Context
Capstone project, CECOS University
Status
In development

Problem

Reviewers want to know whether submitted academic writing was machine-generated. Research papers have their own structure, vocabulary and citation style, so a useful detector has to work on that kind of text and say where in the paper its findings come from.

What I did

  • Prepared and balanced labelled datasets of AI-generated and human-written text, with tokenisation, normalisation and cleaning pipelines for Transformer input.
  • Fine-tuned pretrained Transformer models for the classification task with Hugging Face and PyTorch.
  • Evaluated checkpoints on held-out splits with accuracy, precision, recall and confusion-matrix analysis.
  • Built PDF and DOCX parsing that recovers clean, section-aware text for classification and summarisation.
  • Added LLM summarisation that turns model outputs into reviewer-facing reports with per-section findings.

Key decisions

  • Fine-tune, don't train from scratch. Adapting a pretrained Transformer uses language knowledge it already has; the project's data goes into the task itself.
  • Keep section boundaries. Findings map to a section of the paper that a reviewer can open and check.
  • Report precision and recall, not only accuracy. Wrongly flagging a human author and missing generated text have different costs for a reviewer.

Stack

Python, PyTorch, Hugging Face Transformers, TensorFlow, Scikit-learn, CNN and Vision Transformer models, Flask, React, SQLite

Outcome & limits

Still in development, so no final scores are published yet.

Personal project · RAGDemo video

YouTube Knowledge Assistant

Ask questions about a lecture video and get answers drawn only from its transcript.

My role
Ingestion, retrieval, grounding, API
Context
Personal project for studying lecture videos
Evidence
Demo video on LinkedIn ↗

Problem

Long lecture videos are slow to revise from. A general chatbot answers from its own training data and can state things the lecturer never said.

What I did

  • Built an ingestion pipeline that transcribes the video, segments and cleans the transcript, and generates embeddings.
  • Implemented vector search with ChromaDB and deliberate context construction, so answers are grounded in retrieved transcript passages.
  • Evaluated retrieval relevance and answer faithfulness against the source transcripts.
  • Served the system through a FastAPI backend.

Architecture

Key decision

Generation is limited to retrieved passages. That suppresses answers about things the video doesn't cover, which matters more for revision than a fluent but wrong reply.

Stack

Python, LangChain, ChromaDB, OpenAI embeddings, FastAPI, Streamlit

Outcome

Reported in practical use: lecture revision time cut by about half.

Personal project · Agentic workflowNot deployed publicly

ClassMate AI

An autonomous academic-workflow agent. It monitors Google Classroom for new assignments, drafts work with an LLM, and submits only after the user approves, rejects or regenerates each draft.

My role
Agent graph, approval flow, Google API integration
Context
Personal project
Status
Working build, not deployed publicly

Problem

Tracking assignments across courses is manual work. Automating the whole path to submission is risky, because model output can be wrong and a submission can't be taken back.

What I did

  • Built an agent that monitors Google Classroom in real time and routes each assignment through generation, review, regeneration and submission stages.
  • Designed human-in-the-loop checkpoints so the user can approve, reject or regenerate any output before submission.
  • Integrated the Google Classroom and Google Drive APIs.

Architecture

  1. New assignment
  2. Generate draft
  3. Human review
  4. Approve / reject / regenerate
  5. Submit via Drive & Classroom

Key decision

Every draft passes a person before submission. LangGraph's explicit state makes the generate, review and regenerate cycle visible and easy to resume.

Stack

Python, LangGraph, LangChain, FastAPI, Gemini API, Groq API, Google Classroom API, Google Drive API

Limits

Designed around a person approving each submission. It is not meant to run unattended.

How I work

An agent is more than a model call

The model is one component. The engineering is the loop around it, and that loop is what keeps output reliable once clients depend on it.

the loop6 steps
  1. 01 · Brief

    Pin down the task

    Turn loose requests into a spec: outputs, constraints, and facts that must come from the client.

    Web agents

  2. 02 · Plan

    Explicit steps

    Run multi-step work as a graph with inspectable state, so failures point to a step.

    LangGraph at Arfa Kareem · ClassMate AI

  3. 03 · Act

    Bounded tools

    Each tool call has one defined job, which keeps runs predictable and debuggable.

    DX Creativ agents · Document RAG

  4. 04 · Evaluate

    Check before trust

    Faithfulness for retrieval, precision and recall for classifiers, the brief for agent output.

    YouTube assistant · AcademicGuard

  5. 05 · Repair

    Fix the system

    Failure modes from real use become prompt, retrieval, config or code changes.

    Google Ads & SEO agents

  6. 06 · Ship

    People on irreversible steps

    Approval checkpoints before actions that can't be undone, such as submitting work.

    ClassMate AI
